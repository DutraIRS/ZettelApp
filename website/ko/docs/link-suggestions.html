링크 제안

글을 쓰는 동안 링크 제안 패널이 지금 편집 중인 노트와 연결될 가능성이 높은 노트를 나열해요. 링크를 클릭해 연결하거나(옆의 화살표로 링크 유형을 고를 수 있어요), **✕**를 클릭해 제안을 닫으세요. 둘 다 모델을 학습시켜요. 제안에 마우스를 올리면 왜 제안되었는지 볼 수 있어요.

제안은 입력을 멈추고 약 1초 뒤에 백그라운드에서 업데이트되므로 편집기가 기다리는 일은 없어요. 저장하지 않은 텍스트도 사용해요.

동작 방식

ZettelApp은 "이 두 노트를 링크해야 할까?"를 분류 문제로 보고 나이브 베이즈 분류기로 답해요. 노트 q와 모든 후보 노트 c에 대해 여덟 가지 유사도 특성을 계산하고, 그 근거를 하나의 확률로 합쳐요.

특성

특성 측정하는 것
의미 유사도(LSA) 잠재 의미 공간에서의 코사인 유사도예요. TF-IDF 행렬의 절단 SVD(무작위 SVD, 최대 64차원)를 사용해요. 정확히 같은 단어를 거의 공유하지 않아도 관련된 어휘를 쓰는 노트는 가까워져요.
공유 키워드(TF-IDF 코사인) TF-IDF 벡터의 코사인 유사도예요(서브리니어 단어 빈도, 평활화된 역문서 빈도). 제목은 두 배로 계산되고 태그도 포함돼요.
제목 유사도(Levenshtein) 1 − 편집 거리 ÷ 더 긴 제목의 길이.
제목 유사도(Jaro-Winkler) 제목의 Jaro-Winkler 유사도로, 시작 부분이 같으면 점수를 더 줘요.
본문 유사도(Levenshtein) 두 본문의 처음 400자 사이의 정규화된 편집 거리.
공유 태그(Jaccard) 공통 태그 ÷ 전체 태그.
본문에 언급된 제목 한 노트의 제목이 다른 노트의 본문에 단어 단위로 나타나면 1, 아니면 0.
공유 링크(Jaccard) 두 노트가 링크한 노트들의 겹침(그래프에서 삼각형 닫기).

텍스트는 소문자로 바뀌고, 악센트는 통합되며(informação가 informacao와 일치해요), Markdown 문법은 제거되고, 영어, 포르투갈어, 스페인어의 흔한 불용어는 무시돼요. 편집 거리는 RapidFuzz를 사용해요. 사용할 수 없을 때는 순수 Python 비트 병렬 알고리즘이 동일한 결과를 내요.

특성에서 확률로

각 특성 값(0과 1 사이)은 8개 구간 중 하나에 놓여요. 각 특성마다 모델은 링크된 쌍과 링크되지 않은 쌍이 각 구간에 얼마나 자주 속하는지를 기억하고 다음과 같이 추정해요.

P(link | f1 … f8)  ∝  P(link) × Π P(fi | link)

특성의 근거는 로그 가능도비, 즉 log P(bin | link) − log P(bin | no link)예요. 표시되는 확률은 사전 로그 오즈에 (가중된) 근거의 합을 더한 값의 로지스틱 함수예요.

횟수는 어디서 오나요. 모델은 볼트가 눈에 띄게 바뀔 때마다 볼트로 학습해요.

  • 긍정 예시: 링크된 모든 노트 쌍과 수락한 제안(아주 큰 볼트에서는 최대 600쌍을 샘플링해요).
  • 부정 예시: 링크되지 않은 노트의 무작위 쌍(긍정 예시 하나당 세 개)과 닫은 모든 제안이에요. 닫은 제안은 두 배로 계산돼요.

첫날부터 동작하는 사전 분포. 데이터가 없을 때는 각 구간이 디리클레 의사 횟수(기본적으로 특성과 클래스마다 10)로 시작해요. 이는 약한 믿음을 나타내요. 링크된 쌍은 유사도가 높을수록 횟수가 늘고, 링크되지 않은 쌍은 가파르게 줄어요. 새 볼트에서 제안의 순위를 매기기에는 충분해요. 노트를 링크할수록 실제 횟수가 사전 분포보다 커지고 모델이 나만의 링크 방식에 적응해요. 긍정과 부정을 1 대 3으로 샘플링하므로 클래스 사전 확률 P(link)는 약 4분의 1이에요(의사 횟수도 그에 맞춰져요).

두 가지 보정으로 추정치를 정직하게 유지해요.

  1. 레이블 누출 없음. 특성을 계산하기 전에 [[위키 링크]]를 본문에서 제거해요. 그렇지 않으면 인라인 링크가 대상의 제목을 본문에 넣게 되고, 모델이 관련된 아이디어가 아니라 이미 존재하는 링크를 알아보도록 학습하게 돼요. 같은 이유로 링크된 쌍으로 학습할 때 "공유 링크" 특성은 두 노트 사이의 링크를 무시해요.
  2. 상관된 근거에 가중치를 줘요. 나이브 베이즈는 특성이 서로 독립이라고 가정하지만, 일부는 그렇지 않아요. TF-IDF와 LSA는 겹치고, 세 가지 문자열 거리도 마찬가지예요. 상관된 근거를 독립으로 세면 단순한 나이브 베이즈는 과신하게 돼요. 그래서 ZettelApp은 각 특성의 근거에 0.6을 곱해(특성 가중 나이브 베이즈) 확률을 현실적으로 유지해요.

누락되거나 꺼진 특성은 근거가 없는 것으로 쳐요. 특성을 끄거나 계산할 수 없으면 아무것도 더하지 않아요. 나이브 베이즈가 누락된 값을 자연스럽게 다루는 방식이에요.

빠른 순위 매기기

긴 텍스트를 Levenshtein 거리로 비교하는 것이 가장 느린 단계이므로 순위는 두 단계로 매겨요. 먼저 모든 후보를 본문 유사도 특성 없이 채점하고, 상위 150개만 전체 점수를 받아요. 이미 링크한 후보와 닫은 쌍은 제안되지 않아요.

"이유" 툴팁 읽기

제안에 마우스를 올리면 모델의 추정치와 각 특성의 근거를 볼 수 있어요. 양수는 링크에 찬성하고 음수는 반대하는 근거예요. 막대 옆의 라벨은 확률을 요약해요. 강함(50% 이상), 가능성 높음(25% 이상), 가능성 있음이에요.

확률은 정직한 추정치이고, 링크가 드문 볼트에서는 대부분의 쌍이 실제로 링크되지 않았기 때문에 15–30%도 좋은 제안일 수 있어요. 가장 중요한 것은 순서예요.

  • **모델 상세…**는 모델이 학습한 링크된 쌍과 링크되지 않은 쌍의 수, 그리고 각 특성이 얼마나 유용한지(링크된 쌍과 링크되지 않은 쌍의 분포 사이의 대칭 쿨백–라이블러 발산)를 보여 줘요.
  • 닫은 제안 잊기는 닫은 기록을 지워서, 그 쌍이 다시 제안될 수 있고 부정 예시로 더는 계산되지 않게 해요.
