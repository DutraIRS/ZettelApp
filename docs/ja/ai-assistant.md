# ノートに質問 (AI)

**質問**ページ (Ctrl+5) は、**あなたのノートに基づいて**質問に答え、クリックできる引用を付けます。ご自身の API キーで、お好きな AI プロバイダーを使います。完全に任意の機能で、質問するまでは何もどこにも送信されません。

![ノートに質問](../website/assets/screenshots/ask-light.png)

## セットアップ

1. 対応しているプロバイダーのいずれかで API キーを取得します。
2. *ツール ▸ オプション ▸ AI アシスタント*を開きます。**プロバイダー**を選び、**API キー**を貼り付け、**モデル**を選びます (*一覧を更新*で、お使いのキーで利用できるモデルをプロバイダーに問い合わせます)。

プロバイダーごとに複数のキー (たとえば個人用と仕事用) を保存できます。キー一覧の横の*キーを追加…*、*名前の変更*、*削除*を使います。選択中のキーが質問で使われます。
3. **接続をテスト**を押し、**OK** を押します。

| プロバイダー | 既定のモデル | その他の推奨モデル | エンドポイント |
|---|---|---|---|
| **Anthropic Claude** (既定) | `claude-opus-5-5` | `claude-sonnet-5-5`、`claude-haiku-5-5` | `https://api.anthropic.com` |
| **OpenAI** | `gpt-6.1-sol` | `gpt-6-astra`、`gpt-6-luna` | `https://api.openai.com/v1` |
| **Z.ai (GLM)** | `glm-5.3` | `glm-5.3-flash`、`glm-4.7-flash` | `https://api.z.ai/api/paas/v4` |

お使いのキーでアクセスできる任意のモデル ID を入力できます。**エンドポイント (任意)** はアドレスを上書きします。たとえば、Z.ai のコーディングプランのエンドポイント、OpenAI 互換のプロキシ、お使いのコンピューター上で動作するモデル (`http://localhost:…`) を使う場合です。アドレスは `https://` を使う必要があります。平文の `http://` は `localhost` のみ受け付けられます。

Claude では**エフォート** (低から最大) も設定できます。エフォートが高いほど回答前により深く考え、コストも増えます。既定は*中*です。

## 自分の LLM を使う

質問機能は、選んだプロバイダーの**ご自身のアカウント**を使うので、使用料はそのプロバイダーからあなたに請求されます。ZettelApp には独自の AI サービスはありません。API キーは **Windows 資格情報マネージャー**に保存され、設定ファイルには決して保存されません。

- **プロバイダー**: Anthropic Claude、OpenAI、Z.ai (GLM)。*ツール ▸ オプション ▸ AI アシスタント ▸ プロバイダー*で選べます。**モデル**は一覧から選ぶか (*一覧を更新*で、お使いのキーで利用できるモデルをプロバイダーに問い合わせます)、お使いのキーでアクセスできる任意のモデル ID を入力します。
- **自分のサーバー**: **OpenAI スタイルの chat completions** API を提供するサービスなら何でも使えます。**OpenAI** を選び、**エンドポイント (任意)** にそのベースアドレスを設定します。たとえば `https://my-proxy.example.com/v1`、`http://localhost:11434/v1` (Ollama)、`http://localhost:1234/v1` (LM Studio) です。平文の `http://` は `localhost`、`127.0.0.1`、`::1` のみ受け付けられ、それ以外はすべて `https://` を使う必要があります。これらのローカルアドレスでは、**API キー**は空のままでもかまいません。
- **確認する**: **接続をテスト**を押します。ローカルモデルの場合、質問もノートもコンピューターの外に出ることはありません。
- **送信されるもの**: 質問と、お使いのコンピューター上で見つけた最も関連性の高いノートだけです。ノートの数は、質問ページの**ノート数**ボックスで指定します (既定は 8)。*送信された情報源*の一覧には、実際に送られたノートが正確に表示されます。

## 質問する

質問を入力して**質問** (Ctrl+Enter) を押します。**検索対象**で探す場所を選びます。コレクション全体、開いているノートとリンクされたノート、またはタグが付いたノートです。送信する**ノート数**も選びます。

処理の流れ:

1. ZettelApp は、[リンク候補](link-suggestions.md)と同じ TF-IDF と LSA の類似度を使って、**お使いのコンピューター上で**最も関連性の高いノートを見つけます。*現在のノートとリンクされたノート*では、開いているノートが常に先頭になります。
2. 質問とそれらのノートがプロバイダーに送信されます。ノートは最大 120,000 文字です。収まるように切り詰められたノートの末尾には、「[note truncated]」という目に見えるマーカーが付きます。**送信された情報源**の一覧には、どのノートが送られたかが正確に表示されます。
3. 回答は書かれるそばからストリーミングで表示されます。`[[20261027153012]]` のような引用は、ノートへのリンクとして表示されます。**停止**でキャンセルできます。

モデルには、ノートだけから答えること、ノートに答えがない場合はそう伝えることが指示されています。**コピー**は回答を Markdown としてコピーします。**ノートとして保存**は、回答を `ai-answer` タグ付きの新しいノートとして保存し、情報源への `cites::` リンクを付けます。

## プライバシーと安全性

- **送信されるのは質問した内容だけ**: 質問と、*送信された情報源*に表示されるノートです。質問する前に、お知らせでこのことが通知されます (*今後このメッセージを表示しない*にチェックを入れると、表示されなくなります)。
- **API キー**は **Windows 資格情報マネージャー** (`ZettelApp/llm/<provider>`、追加のキーは `ZettelApp/llm/<provider>/<キー ID>` として) に保存され、設定ファイルやログには決して保存されず、表示されるエラーメッセージからも取り除かれます。*削除*でこのコンピューターから削除できます。
- **モデルはツールを持ちません。** Web を検索したり、コードを実行したり、ノートを変更したりできないので、ノート (またはインポートしたファイル) に隠された指示で何かをさせることはできません。回答は、ノートと同じ安全なレンダラーで表示され、HTML やスクリプトは含まれません。
- Claude では、ZettelApp は Anthropic の公式 SDK を使い、**サーバー側のリフューザル フォールバック**を有効にします。リクエストが安全性分類器に拒否された場合、Anthropic は推奨のフォールバックモデルで再試行します。これは Claude Opus 5.5、Opus 5、Sonnet 5.5、Fable 5.1 に適用されます。
- 送信した内容には、各プロバイダー自身の利用規約とデータポリシーが適用されます。

## 別のプロバイダーを追加する

プロバイダーは小さなレジストリ (`zettelapp/core/llm.py` の `PROVIDERS`) にあります。既存のプロトコル (Anthropic の Messages API、または多くのプロバイダーが提供する OpenAI スタイルの chat completions) で通信するサービスは、**1 つのエントリー**で済みます。名前、エンドポイント、既定のモデル、ユーザーがキーを取得するページです。新しいプロトコルには、小さなアダプタークラスが必要です。[開発](development.md)を参照してください。
